# 最新天气对话失败与恢复记录

本记录针对原对话“给我一个能显示全量天气信息的 app”（会话 `841qjgu7tel`）。修复后使用原配置的 GPT-6 luna 恢复执行，最新 Run `f329cbb4-0676-401c-91f1-4572cc73b2d5` 已进入 `waiting_user / wait_schema`，错误为空。新提案包含 8 项功能验收条件，正在等待用户审批具体网络、定位及私有文件权限；该对话尚未开始生成或运行新的 App。

## 发现与修复

- 方案生成没有得到合法的 App 功能 ID 目录，验收条件又过于笼统。生成和 refinement 现使用同一目录，按功能、恢复状态及界面要求拆分可检查的条件。
- 语义复核重复要求已声明的数据来源，并把未指定的查询参数与响应映射当作设计阶段的必需项。复核现检查完整目标和实际授权依赖；具体实现细节只在请求或批准计划明确指定时要求。真实功能、缺失状态与权限检查仍然保留。
- 一次局部修复仍无效时，外层曾丢弃具体诊断并重新生成，耗尽预算。现在这类确定性校验失败保留初次与修复诊断并终止；瞬态错误、配置错误和预算错误维持原分类。
- 原生传输把正常流式片段计入 1024 条控制消息上限。一个使用相同安全约束的 GPT-6 luna 诊断任务在第 1025 条消息被拒绝，其中已接受 1004 条输出片段，总计 357036 字节，只有 3 个 item。修复后，精确绑定当前 thread、turn 和已知 agentMessage item 的合法片段使用独立的 8192 条上限；控制消息仍为 1024，所有原始字节仍受 2 MiB 总量及单行上限约束。未知消息、身份不匹配、callback、item 和超时检查继续生效。诊断日志只记录限额类别和标量计数。
- 第一次部署新增流式校验时漏掉了现代协议的 `emittedAtMs` 通知时间戳，真实恢复因此被拒绝。后续仅兼容 pinned 0.159.3 协议定义的可选 int64 时间戳；未知字段、布尔值、错误类型和溢出值不能获得流式额度。协议依据来自已安装二进制生成的 JSON Schema，并由同版本源码复核。
- 方案修改报错后，已消费的修改反馈没有保存，重试会丢失输入。恢复现在仅保留和核实已解析的 schema `refine` 要求，用同一草稿和反馈继续修订，并产生新的待审批卡。旧批准、拒绝及其他动作不被当作新授权重播。

## 真实恢复过程

原始两次运行分别在 `align_schema` 消耗 64351 和 68831 个报告 token 后失败，均未进入 Coding Agent。首次修复后的恢复用了 4 次调用、额外 26433 token，正确保留了语义校验失败及具体诊断。第二次恢复用 2 次调用、额外 14436 token 到达待审批，但人工核对发现地点搜索的 host/path 是模型猜出的错误地址；随后真实 refinement 触发了传输输出上限。

地点搜索已按 [Open-Meteo 官方地理编码文档](https://open-meteo.com/en/docs/geocoding-api) 修订为 `https://geocoding-api.open-meteo.com/v1/search`，天气预报按 [官方天气文档](https://open-meteo.com/en/docs) 使用 `https://api.open-meteo.com/v1/forecast`。核实结果通过现有 refinement 反馈交给模型，没有手工修补生成的提案或 App。

流式上限修复后的真实重试又因时间戳字段拒绝了正常通知；一个额外的诊断任务确认其 thread/turn 与已知 agentMessage item 均正确，只有通知 envelope 多了 `emittedAtMs`。诊断记录只含结构及计数，没有原始输出或提示正文。

最终恢复本次记录了 4 次模型调用，额外 34927 个报告 token，产生新的待审批方案。仍使用既有的每次重试 64000-token 窗口，没有提高全局预算。两次失败的原生 refinement 和两次独立诊断没有返回 usage；上述 token 计数不包含这部分未知用量。

## 验证及证据边界

完整后端：2072 项通过，16 项既有跳过；Ruff、UML、差异检查和本地镜像构建通过。前端在本轮较早通过 370 项测试、构建和 oxlint，此后前端源文件未变。最终部署源码 hash、模型审计 hash、具体权限来源及验收条件见 [机器可读记录](weather-workflow-recovery.json)。

原始两次运行的既有配置还调用了 Jev shadow router；这些记录在 JSON 中单列，不能称原始日志只包含 Luna。方案生成、功能复核及本次恢复的推理均使用 GPT-6 luna；本次从修订阶段恢复，没有重新路由。

结构校验和功能复核不能自动证明任意外部接口存在或可用。网络来源提示约束属于模型指导；这次具体端点由人工查阅官方资料核实，未执行实时天气请求。该对话的 App 代码、实际数据集成及图形界面仍需在权限审批后生成并验收。此前独立天气/CRUD 案例的浏览器结果见 [图形界面评估报告](coding-agent-ui-quality-results.md)，不能替代本对话的最终 App 验收。
