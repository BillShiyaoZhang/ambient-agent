# Native Codex 0.159.3 acceptance (2026-10-02)

## Scope

This verifies transport compatibility for modern Codex as Ambient primary/fast models. Execution used
an actual Linux Debian 12 aarch64 container and the official pinned `codex-cli 0.159.3`. The adapter
and probes lived in temporary container directories, without replacing service code, restarting
services, or changing model bindings.

Probes used a separate inference home, temporary cwd outside projects, ephemeral threads, and
read-only/no-network policy. Only a trusted `auth.json` symlink shared the existing CLI-managed login;
authentication contents were neither read nor copied. No workspace data was submitted. Text and tool
selection each had a 60-second bound; tool selection validated JSON without executing a tool.

An unauthenticated actual-CLI probe first checked `initialize` and effective `config/read` without
model requests. Pinned public source and generated protocols formed
`tests/fixtures/codex_native_0_159_3.json`, containing only model metadata and configuration projections,
without account information. The adapter follows the [Provider contract](../integrations/llm-providers.md).

exactly matched `skip_host_skill_discovery`, without ignoring arbitrary upstream warnings.

## Regression and limits

Modern slices recorded actual failing tests before implementation: strict JSON for four GPT-6 models,
async filtering, stable item ID type/delivery, known account/warning shapes, unsupported versions,
wrong identities, unknown tools, and unsafe configuration rejection. The legacy `0.145.0` profile
retains separate regression. Final complete backend: 1225 passed, 16 skipped; frontend: 358 passed,
with build and lint passing. Ruff, UML, and paired documentation verification remain handoff gates.

The modern external CodeMode host remains disabled; these results do not establish internal CodeMode
execution. Actual generation covered only `gpt-6-luna`; other models still require exact-selection
account-access tests. This record does not establish full App, durable Run, recovery, public-access,
or repeated Harness evaluation acceptance. Local source has not been deployed to the running services;
after updating, resync the model catalog to refresh saved role compatibility.
