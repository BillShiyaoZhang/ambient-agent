# UI Quality Evaluation Results

## Paired result

The final paired report passes both cases. The forecast dashboard passed 22 browser checks; the repaired follow-up dashboard passed 23. Both were verified in the production widget frame and SDK using Chromium 154.0.8037.97 and Playwright Core 1.62.0, with initial screenshots at 320 and 640 CSS pixels in light and dark themes.

The paired report is [coding-agent-ui-quality-paired.json](../../verification/coding-agent-ui-quality-paired.json), and the per-case generation selection is [coding-agent-ui-quality-selected-generation-evidence.json](../../verification/coding-agent-ui-quality-selected-generation-evidence.json). It links each retained production app digest to its immutable generation source and browser report. The selected cases are the original forecast app and the repaired follow-up app.

The forecast chart uses fixture-driven CSS geometry for the temperature range marks. Changing a fixture high changes both mark height and the visible value. The initial view shows three daily detail rows; activating the disclosure with the keyboard reveals all seven days and service details. The historical check ID `svg-data-chart` now accepts SVG plotting geometry or equivalent CSS plotting geometry; it does not require the model to emit SVG.

The original follow-up app's browser report records a real retry bug: after an injected private-file write failure, Retry reread the file and discarded the unsaved item. The initial app and failure report remain unchanged. One focused model repair used this observation to request preserving the edit and retrying the pending write; the repaired app passes CRUD, keyboard, storage-read recovery, write-failure recovery, and responsive checks. Its feedback explicitly required preserving unsaved input after a failed write. The shared guide gained the equivalent general rule afterward, so this repair was driven by case-specific feedback.

The initial run made three production generation dispatches for two retained apps: one forecast and one CRUD artifact were retained, while a duplicate forecast generation completed staging but was discarded when the retention destination collided. One focused production model call then repaired CRUD, for four actual dispatches total. A pre-dispatch collision guard now prevents that duplicate-call pattern. No generated controller was manually patched, and no live weather or external network was accessed.

The initial generation and repair used shared-guide SHA-256 `2002d5ee19cfb9710ed599207d8139312e6e38247f52cc1ddda77ca483a1f99d`. The general rule to preserve pending writes after a failed write was added afterward; the currently deployed guide has SHA-256 `f1a9d811e4c1a3eb3724da2d0e68f75bf1def1039b2bd5f817a3f482ca98f2cc`.
