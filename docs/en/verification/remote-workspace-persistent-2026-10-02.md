## Diagnosed issues and repair boundaries

The historical UI issue came from treating durable Run payloads as current commands. Dialogs now require the current Run to be `waiting_user` with an interaction still `pending`. Changing conversations or completing an interaction clears frontend presentation without changing persistent Runs. Disconnection preserves valid requests; a failed lookup neither establishes a new grant nor discards an existing request. Mutation notifications use the remaining soft window from the original event time instead of restarting the countdown during replay.

The current implementation can still issue repeated GETs for a Run's historical permission payload and `interaction_requested` events. Version checks discard stale responses without merging HTTP requests already sent. This cost boundary is statically confirmed but has not been established as the cause of a large bill. Request coalescing remains an optimization to evaluate; the frozen Ambient stream contract has not changed.

The observed disconnection on old a3540b1 comes from counting a node's control frames, WebSocket data, and HTTP responses in one rate bucket before parsing the message type. Bounded Red reproduction exhausts that budget with 1199 data frames and one accept, followed by whole-Tunnel closure with 1012 and no backpressure. Legitimate history replay in one page can consequently close other connections.

The first new-image browser attempt's response-body timeout remains separate. For create-session verification, the second harness removes the tester's additional `pageResponse.json()` read, which the product's create-session flow does not require. Product model updates still read `res.json()` through `jsonRequest`; the second harness instead verifies model evidence through the request DTO and persisted GET. These are evidence-collection changes without product HTTP changes. The first attempt did not observe `loadingFinished`, and the stalled body read has no final cause attribution. Subsequent UI success is not evidence that another HTTP product bug was identified and repaired.

Proposal commit 0187361 separates control and data budgets: control remains at 1200, while known and late data frames still count toward the node's data budget of 60000 frames and 64 MiB of encoded wire messages. Exceeding the node budget still closes the Tunnel. A slow browser or backpressure in one lane isolates that lane without closing other connections. Queues and late-lane tombstones are bounded; tombstones have a limit of 256 and a TTL window. All 105 source tests and fixed-Linux-image verification pass, the production image is deployed, and the Ambient event protocol is unchanged. The second cold Chrome attempt completes full zero-cursor replay, 30-second stability across all three connection types, and one normal-UI chat round trip. This observes single-page recovery from the replay issue, without establishing long-term or multi-user capacity.

Linux evidence preserves the first execution and retry. The first protocol run reported 91 passes, but collecting logs/proof from tmpfs failed. After repairing the test harness, the second final run produced valid proof: 91 passed, zero failures/skips. This was an evidence-collection failure; it is neither hidden nor presented as an observed product failure. Final tests ran with no network, read-only rootfs/fixtures, and no published ports, without model or production-cloud calls. The owned test container was removed, and the actual production app and safeguards match the fixed source archive.

Public artifact checksums: source archive SHA-256 `a1251068a1eeddf66ca0ea7a59726779e2223fc9c680733d6a16baa46adc7124`; image gzip archive `d0ed16502694bf05f38720e713c89495084fabd9776ccea118ba84f04c0c18d7`; production app and safeguards source respectively `5fae8ec4a489e4b02656aaa2a82c4d422789b75af0751b64b0c44ecfc2a21791` and `6a98480dccb2ee3559814cdab0559b9ff2714b457073b6924bacd8d37bab91f4`.
